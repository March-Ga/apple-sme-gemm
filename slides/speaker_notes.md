## 01. SME and Accelerate on Apple M4 Pro

This deck explains the implementation currently present in the repository. The SME backend uses size-dependent kernels as one implementation: direct B through N=512 and a blocked 16×64 kernel above it. Accelerate is the other backend. All results include preparation of the inputs. There is no historical baseline implementation in the worktree.

## 02. SME is an instruction set; Accelerate is a library

SME is an Arm architectural extension exposed through instructions and C intrinsics. SME2 adds grouped-vector operations used in this implementation. Accelerate is Apple’s framework, including BLAS and LAPACK. Its cblas_sgemm entry point selects an internal implementation appropriate to the CPU. This experiment does not inspect that library’s internal instruction path, so it cannot isolate the effect of using SME versus disabling it. [1] https://arm-software.github.io/acle/main/acle.html [3] https://developer.apple.com/accelerate/

## 03. One outer product updates many output values

For one value of k, take a column of A and a row of B. Their outer product adds a rectangular update to C. Repeat for every k. FMOPA performs the predicated outer-product accumulate into a ZA tile. Our numerical toy example uses a two-value column and a three-value row; real FP32 vectors here have 16 lanes. Each FMOPA updates 256 values with fused multiply-add operations, or 512 nominal FLOPs. [1] https://arm-software.github.io/acle/main/acle.html [2] https://scalable.uni-jena.de/opt/sme/micro.html

## 04. ZA exposes four logical FP32 tiles at 512-bit SVL

At a 512-bit streaming vector length, a Z vector holds 16 FP32 values. ZA contains 4096 bytes and its FP32 view provides four 16×16 tiles. The diagram shows logical tile views rather than physical SRAM geometry. The implementation is specialized to this SVL and rejects others. Public SME computation functions use locally-streaming/private-ZA attributes; internal tile helpers share the caller’s ZA, keeping mode transitions outside the inner tile loop. Explicit zeroing starts a new output tile; subsequent K blocks reload C. [1] https://arm-software.github.io/acle/main/acle.html [2] https://scalable.uni-jena.de/opt/sme/micro.html

## 05. One SME backend adapts its data path to matrix size

For N≤512, the implementation transposes A into 16-row panels and loads B directly in its original row-major form; a 32×32 output tile uses all four ZA tiles. For larger matrices it packs B into 64-column panels and uses a blocked 16×64 kernel. This applies to every supported dimension, including a final 32-column tail. There is no call to a separate legacy backend and no delegation to Accelerate. Supported dimensions are multiples of32 from32 through8192. These size-dependent choices are parts of the same final implementation, not selectable experimental versions.

## 06. Build contiguous A panels by reading ZA columns

The diagram labels a 4×4 toy tile by row and column. The actual packer loads16 horizontal slices of a16×16 FP32 block into ZA, then reads columns in groups of4 using svread_ver_za32_f32_vg4 and writes them contiguously. The packed panel puts16 A values for one k next to one another, exactly as the FMOPA operand requires. This preparation is timed on every SME call. [1] https://arm-software.github.io/acle/main/acle.html

## 07. For N≤512, B can be consumed without packing

A0 and A1 represent two groups of16 output rows. A two-vector B load supplies B0 and B1, representing32 consecutive output columns. Four outer products fill the quadrants of a32×32 output tile. A is prepared with the ZA transpose; B requires no packing or extra buffer. This saves work at sizes where copying B is not beneficial. The small path traverses all K values before storing the completed tile.

## 08. The 16×64 kernel reuses one A vector four times

Four logical16×16 ZA tiles are arranged across a16×64 output region. One A vector is reused with four B vectors from svld1_f32_x4. A tuple is consumed in the same K iteration, keeping its live range short; the loop is unrolled four times. This shape performs2048 nominal FLOPs/k and loads320 logical operand bytes/k, excluding C traffic and cache reuse. Its performance depends on the complete grouping, packing and blocking design; tile shape alone does not guarantee efficiency.

## 09. Load, consume, and retire the tuple in one iteration

The code is the inner arithmetic loop used in the final large-matrix kernel. va is reused by all four outer products. vb is loaded and consumed within the same iteration. The build checks that all four FMOPA tile destinations and grouped vector loads are present in the generated object code. These structural checks complement numerical tests and end-to-end timing; they do not establish peak throughput by themselves.

## 10. Bound the working panels and handle the last 32 columns

Compute traversal is K block, N block, M block,64 columns,16 rows. Full macro-panels have logical sizes256×2048×4=2 MiB for A and2048×512×4=4 MiB for B, not guaranteed cache residency. B packing visits32 K rows and256 columns at a time, keeping accesses local. If N is not divisible by64, only the final32-column B panel is extended with32 zero columns. A is not padded; C retains its N stride, and loads/stores for nonexistent output columns are skipped. No other implementation is used. Tests cover every packed value including zeros, output guards, and partial K blocks.

## 11. Compare the same complete row-major matrix product

Both backends compute C=A×B with FP32 row-major inputs, alpha1 and beta0. SME packing is included on every call. Allocation, initialization, verification, process startup and calibration are excluded. One calling thread uses USER_INITIATED QoS; Accelerate BLAS is explicitly forced to one thread. The full suite has eight sizes, three randomized rounds and seven batch-average samples per backend/size; calibration targets at least30ms per batch. Inputs are reused. Throughput is2N^3 divided by pooled median seconds. Speedup is the median of Accelerate/SME timing ratios paired within each round. IQR shading is not a confidence interval. [4] https://developer.apple.com/documentation/accelerate/blas_threading_single_threaded

## 13. Read the ratios alongside absolute performance

The table is generated from summary.csv and speedups.csv. Each displayed row is a measured size. Ratio values above1 mean SME is faster. These results describe this machine, compiler, timing protocol and input reuse pattern. No per-optimization or isolated-instruction-set uplift is claimed.

## 14. Build, verify, benchmark, and plot

The build records source and binary hashes and audits generated matrix instructions. Tests verify all packing destinations and padding, compare both backends to an independent scalar double reference, and check repeated overwrites and output guards with ASan/UBSan. Benchmark jobs check results before and after timing. The cleanup validation compares the same optimized algorithm before and after repository simplification using randomized interleaving; its measurements are separate evidence rather than another runnable backend.
